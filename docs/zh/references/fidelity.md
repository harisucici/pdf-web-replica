# 尽可能忠实复刻的迭代流程

[中文](fidelity.md) | [English](../../../references/fidelity.md) | [日本語](../../ja/references/fidelity.md)

## 目标与分工

目标是原 PDF 页面，不是通用阅读器主题。`build` 只提取初始草稿，Agent 还必须分析、重建、查看并修正。脚本不能自动把任意扫描件变成最终排版。只要存在能执行的具体修正，就应继续；若缺少字体、原件不可读或浏览器/OCR 不可用，保留逐页记录，说明具体差异和恢复路线，不能用成功提示掩盖。

不能把其他文档手工调好的排版当作通用 PDF 转换器。可以复用绘制方法和阅读器外壳，但新 PDF 的尺寸、版式类别、颜色、区域和字体都必须来自它自己的原页。

## 1. 全量清点与原件分析

构建完整请求范围后执行：

```sh
python scripts/run.py analyze outputs/book
```

- `analysis/contact-*.jpg` 是原件总览，每张 24 页。
- `analysis/00001.json` 保存原件色板和连通颜色形成的区域、线条候选，使用显示页面的 PDF 坐标。不会识别字体、推断圆角，也不证明候选一定是矩形。文字孔洞、照片和渐变都可能影响结果，必须查看后再重建；不能把字形连通区域描成假文字。
- `reconstruction-plan.json` 记录全部已选页、暂定版式分组和任务。`family_override`、`notes` 保留手工判断。分组相似只是提示；不同标题、表格、页脚、颜色和例外仍需逐页检查。

按版式类别组织工作，再验证每一页。识别面板、分栏、单元格、图示、插图、正文与注音，注意隐藏 OCR、混合页和拼接扫描图。源页参考图与正常发布内容分开。

## 2. 重建并同步

原生页尽量保留有效的文字基线、矢量、字体和真实插图；检查不支持的裁切、透明度、批注、Type 3 字体和字形映射。扫描页用带坐标 OCR 加独立 CSS/矢量区域，补齐分区和线条。仅移除扫描底图不算重建。

编辑页面 JSON 或导入补丁：

```sh
python scripts/run.py apply-layout outputs/book --page 12 --json work/page-12-layout.json
python scripts/run.py refresh outputs/book
```

补丁允许 `blocks`、`text`、`shapes`、`images`、`web_layout`、`background_color`、`reference_image`，不能设置验收标记。要切回通用 SVG 渲染，显式设置 `web_layout: null`。改动会重置校验。更新 OCR/文字但保留旧手工排版时，`layout_needs_sync` 会阻止验收，直到用 `apply-layout` 同步两者。可见文字、`blocks`、提取全文和搜索内容应一致。

按原比例匹配填色、描边、圆角、间距、行高、基线、字距、宽度、粗细、斜体、下划线、竖排/RTL 和叠放。细小注音、上标需放大原件区域，仅抄写真实内容。通过实际字形和行宽核对字体，不能只看字体名就宣称相同。无法恢复的原字体和替代差异必须保留为明确问题。

## 3. 采集真实网页的默认视图

刷新生成 `qa/capture-requests.json`，包含每页当前的 `render_fingerprint`、相对 URL、截图与元数据文件名。宿主需要 HTTP 时本地启动服务，使用实际可用且允许的浏览器工具，先确认真实接口。无需另一套 OCR skill；只会读图的视觉工具也不自动等于浏览器渲染器。

打开 `index.html?qa=1#page=12`。纯页面模式隐藏阅读器外壳，1 PDF 点对应 1 CSS 像素。等待 `#paper[data-qa-ready="true"]`，读取并解析 `#pdf-replica-qa` 的 JSON；这也适用于只能读取 DOM 的宿主，允许时还可读 `window.PDF_REPLICA_QA`，它会等待字体、HTML 图片和动画帧。记录示例：

```json
{
  "page": 12,
  "render_fingerprint": "从实际已就绪页面读取",
  "default_view": true,
  "page_only": true,
  "ready": true,
  "visible_text_elements": 42,
  "paper_bbox": {"x": 0, "y": 0, "width": 612, "height": 792}
}
```

截取 `paper_bbox` 对应的实际页面，不包含工具栏或外围空白，并遵守截图工具对 CSS/设备像素的约定。保存为 `work/browser-captures/00012.png`（也支持 JPEG）。将实际已就绪记录保存为 `00012.json`，另加 `captured_with` 说明真实工具和截图方法。不能猜测并手填 ready、文字数量或指纹。全部请求页都要采集，可以分批。

不能把 PDF 参考 PNG、原页对照模式、图片背景网页或合成测试图片当作真实网页证据。图片与自身比较得到零差异毫无意义。没有真实浏览器截图能力时，应将视觉证据保留待处理，诊断具体缺失能力，不编造工具，也不能照样标记排版通过。

## 4. 比较、诊断、修正、再比较

```sh
python scripts/run.py compare outputs/book --captures work/browser-captures
```

可用 `--pages 12-24` 分批。全部请求结果都会记录，包括截图缺失或无效。`qa/comparisons/` 包含每页并排图、50% 叠加图、差异图、JSON 指标和差异最大的区域。截图复制到 `qa/captures/`，绑定当前内容与原件哈希。

截图必须符合页面宽高比，只将源参考图缩放到截图比例，不拉伸截图掩盖几何错误。诊断默认值为单通道差异容差 24、差异像素占比 ≤ 0.01、归一化平均误差 ≤ 0.005、最差 1/64 页面区域差异占比 ≤ 0.10。这不是“99% 还原”的承诺。细小错字可能低于阈值，所以文字、语言仍需独立对照；不能为通过而放宽阈值。

先看大差异区域，再放大小字。修正根因，不盲目整体挪动：裁切与比例、缺失底色、分区位置、字体度量、基线、换行、错字、注音、遮罩或插图。刷新后重截受影响页面再比较，也要检查共用版式中的例外。功能正常不等于视觉一致；全页低误差不能掩盖局部错误表格或缺失注音。

## 5. 记录当前版本验收并审计

实际对照完成后执行：

```sh
python scripts/run.py review outputs/book --pages 12 --checks text,layout,fonts,languages --note "已核对当前原件/网页、文字和全部差异区域"
python scripts/run.py audit outputs/book
```

排版、字体验收必须有当前且在诊断范围内的对比证据。指纹覆盖页面内容、字体/插图文件和实际 HTML/CSS/JS；缓存时间戳会规范化，真实改动会使旧证据失效。截图或原件参考图被修改，同样失效。旧版布尔勾选不够。空白页也要核对原件与显示；未解决 OCR、未同步排版不能通过。

只有范围完整、证据有效、四项真实对照均完成时审计才通过。通过表示记录与当前版本一致，不是自动证明语义或像素绝对相同。交付说明应列出全部剩余差异与实际限制。设备、OS 或浏览器可能用不同方式栅格化字体；应记录无法进一步消除的差异，不能假装恢复了原字体。

## 剩余差异

排版补丁可设置 `remaining_differences`，用简洁列表记录与原件尚未解决的差异，注明区域以及实际障碍。审计会列出它们，且不能记录通过。实际解决后用新补丁更新列表，不能为了通过直接清空。空列表也不能代替浏览器证据与原件核对。截图前清除搜索高亮，高亮状态不属于原件对应的默认视图。
