## 这些检查不能证明什么

不能证明任意 PDF 都像素一致、OCR 全对、扫描原字体可恢复，或没有可恢复数据/密码时仍可处理损坏和加密文件。所有生成文档从草稿开始，保留逐页验收记录。跨平台格式兼容与具体 OCR 能力、宿主权限是不同问题。

合成测试覆盖占页面 58.9% 的扫描图、旋转放置、两张各低于阈值但合计覆盖页面的拼图，以及原生页眉加扫描正文。均不作为插图导出。刷新保留手工文字与备注、排除旧扫描图并重置验收标记；已确认小插图仍可使用。`node scripts/reader_selftest.js` 在最小 DOM 上运行真实 reader，检查旧数据、仅有矩阵、bbox 不一致、拼接和未确认图片被隐藏，同时保留已确认小插图与可见可选文字。这是渲染回归检查，不能替代原件全页视觉对照。

## 原件驱动的复刻流程：本地开发检查

`scripts/fidelity_selftest.py` 通过 16 项合成组件检查：颜色/区域、完整任务/总览、手工备注保留、当前视觉证据、稳定构建时间戳、页面/渲染器改动后失效、拒绝补丁设置验收和原页对照截图、差异/最差区域报告、拒绝大差异、OCR/排版同步、截图宽高比、明确剩余差异和 OCR 回退路线。图片仅用于测试比较数学，不是浏览器截图，不能当作任意文档已重建的证据。

另用真实浏览器打开新的合成原生 PDF 对应网页的 `?qa=1` 模式：显示可见可选文字和独立分区，没有原页图，阅读器外壳隐藏，页面矩形为正确的 360×480，并给出绑定当前指纹的就绪 DOM 元数据。对不能读应用全局变量的宿主，额外提供 DOM JSON。这验证采集协议，不证明全书像素一致或任意扫描件都能自动重建。
