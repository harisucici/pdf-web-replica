# 恢复方案

[中文](recovery.md) | [English](../../../references/recovery.md) | [日本語](../../ja/references/recovery.md)

先接受 PDF 任务，清点可用能力并选择真实处理路线，不在检查前笼统回答“不支持 PDF”。继续独立页面或文件，同时记录具体障碍。不声称任何软件能保证处理所有可能的字节流。

| 情况 | 恢复方法 |
|---|---|
| 没有 Python/PyMuPDF | 用 `scripts/bootstrap.py` 建立隔离环境并使用返回的解释器。无法安装时，用已有且允许的 PDF 或宿主文档工具，保留同样的逐页记录和格式。 |
| 原生提取为空 | 渲染页面，区分空白与扫描后再 OCR。没有文字不证明真空白。 |
| OCR 后端不可用 | 用可用的 macOS Vision、带所需模型的 Tesseract、外部 JSON 适配器或已配置的视觉工具。都无法执行时报告缺少的能力。 |
| 缺少 OCR 语言 | 允许时安装模型，或换已配置后端，不将其他文字体系静默按英语识别。 |
| 密码错误或加密 | 使用已授权的密码，通过 `--password-env` 传入；否则说明需要密码。不暴力破解或绕过加密。 |
| 语法损坏 | PyMuPDF 尝试解析修复；构建也会尝试用可用的 `qpdf`/`mutool` 生成独立工作副本。保留原件。所有读取器均失败时报告实际错误，请求可恢复的源文件。 |
| PDF 文档包或内嵌 PDF | 运行 `attachments input.pdf --out work/embedded`，检查 `attachments.json`，按用户范围批量处理内嵌 PDF。提取文件名被限制在输出目录内，不执行附件。 |
| XFA 或不支持的交互内容 | 检查时识别，用支持该表单的渲染器或导出器取得视觉参考，再重建实际字段文字和形状。标准文字提取不证明 XFA 完整。 |
| 超大页面或长文档 | 渲染按像素面积调节以避免内存耗尽。逐步处理全部请求页，必要时提高局部分辨率并续跑，不设任意页数上限或跳过低清细节。 |
| 错误 CMap、轮廓文字、Type 3 字形 | 从渲染结果 OCR 后重建 Unicode，字体及图形/文字分类不确定时保留标记。字母轮廓不是可选择的原文。 |
| 复杂表格、图表、数学 | 尽可能使用原生图元与文字，检查单元格、标签、符号、阅读顺序。有配置时使用专用 OCR。除非用户明确接受，截图或普通 Markdown 表格不是忠实替代品。 |
| 浏览器白屏 | 检查加载/错误提示、页面脚本、请求竞争、页面几何、滚动位置。真实空白页显示独立提示。按交付方式测试本地与托管环境。 |

内置 Tesseract 语言别名包含 `en→eng`、`ja→jpn`、`zh→chi_sim`、`zh-hant→chi_tra`、`ko→kor`，其他已安装模型代码原样传递。此列表不是允许语言的限制；外部适配器无需修改核心技能即可支持其他引擎和文字体系。

恢复方案不授权修改沙箱、关闭防护、未经许可上传到新服务商或隐瞒未完成页面。宿主主动施加的工具与技能限制仍然有效。
