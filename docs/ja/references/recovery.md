# 復旧方法

[中文](../../zh/references/recovery.md) | [English](../../../references/recovery.md) | [日本語](recovery.md)

まず PDF の依頼を受け、利用可能な能力を調べて実行できる処理経路を選びます。確認前に一律「PDF 非対応」とは答えません。個別の障害を記録しつつ、独立したページやファイルは続行します。あらゆるバイト列を必ず処理できるとは主張しません。

| 状況 | 対応 |
|---|---|
| Python/PyMuPDF がない | `scripts/bootstrap.py` で隔離環境を作り、返されたインタープリターを使います。インストール不可なら、許可された既存の PDF ツールやホストの文書ツールを使い、同じページ記録と形式を保持します。 |
| ネイティブ抽出が空 | ページを描画し、白紙とスキャンを区別して OCR します。文字がないことだけでは白紙とは判断できません。 |
| OCR が利用不可 | 利用可能な macOS Vision、必要モデル付き Tesseract、外部 JSON アダプター、設定済み画像認識を使います。何も実行できなければ不足能力を報告します。 |
| OCR 言語がない | 許可されていればモデルを入れるか別の設定済みエンジンを使います。別の文字体系を無言で英語として処理しません。 |
| パスワード誤り・暗号化 | 許可済みパスワードを `--password-env` で渡し、なければ必要と伝えます。総当たりや暗号化回避はしません。 |
| 構文破損 | PyMuPDF が解析修復を試します。ビルドは利用可能な `qpdf`/`mutool` でも別の作業コピーを作ります。原本を保持し、全リーダーが失敗したら実際のエラーを報告して復旧可能な原本を求めます。 |
| PDF ポートフォリオ・埋め込み PDF | `attachments input.pdf --out work/embedded` を実行し、`attachments.json` を確認して、依頼範囲の埋め込み PDF をバッチ処理します。抽出名は出力内に限定され、添付物は実行しません。 |
| XFA・未対応の対話要素 | 検査で特定し、対応レンダラーやエクスポーターで見た目を取得して、実際の項目文字と図形を再構築します。通常の文字抽出だけで XFA の完全性は示せません。 |
| 巨大ページ・長い文書 | 描画のピクセル面積を調整してメモリ不足を避けます。全対象を順次処理し、必要箇所の解像度を上げ、再開します。任意のページ数上限や低解像度の細部の黙示的省略は行いません。 |
| 不正 CMap・アウトライン文字・Type 3 | 描画を OCR して Unicode に再構築します。不確かなフォントや文字/ベクターの分類は未確認にします。文字輪郭は選択可能な原文ではありません。 |
| 複雑な表・図・数式 | 可能なら元の図形と文字を利用し、セル、ラベル、記号、読み順を確認します。設定済みなら分野別 OCR を使います。利用者が明示的に認めない限り、画像や単純な Markdown 表は忠実な代用にはなりません。 |
| ブラウザーが白い | 読み込み・エラー表示、ページスクリプト、リクエスト競合、座標、スクロールを確認します。本当の白紙には専用の表示を出します。納品方法に応じてローカルと公開環境を試します。 |

付属 Tesseract の言語別名は `en→eng`、`ja→jpn`、`zh→chi_sim`、`zh-hant→chi_tra`、`ko→kor` です。他のインストール済みコードはそのまま渡します。これは PDF の対応言語の限定リストではありません。外部アダプターにより、コアを変更せず別エンジンや文字体系を利用できます。

これらは復旧手順であり、サンドボックス変更、安全機能の無効化、未許可の新プロバイダーへのアップロード、未解決ページの隠蔽を許可するものではありません。ホストが意図して設けた制約は引き続き有効です。
