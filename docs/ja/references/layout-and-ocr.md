# レイアウトと OCR の手順

[中文](../../zh/references/layout-and-ocr.md) | [English](../../../references/layout-and-ocr.md) | [日本語](layout-and-ocr.md)

## レイアウト前に全体を確認

全ページの記録を読みます。文書にはスキャン、本物の文字、既存の不可視 OCR、ベクター図、表、フォーム、異なるクロップや回転が混在します。最初のページだけで全体を判断しません。CLI は可能な限りネイティブベクター、本来の小画像、座標付き Unicode を保持し、大きなページ複製画像を除きます。スキャンは OCR 後もレイアウトの再構築が必要です。

既定の `site/` に原本ページの画像背景は入りません。原本 PNG は比較用の別ディレクトリ `references/` に置きます。大きな写真と文字を含むページスキャンは別物です。`images` に加える前に図版を分類・分離し、ページを SVG にトレースした文字輪郭を独立した Web テキストとは呼びません。

## ネイティブの座標

表示時のクロップと回転に正規化した、ポイント単位の PDF 座標を使います。ネイティブ文字には基線の始点、角度、サイズ、送り幅があります。付属ビューアーは輪郭や画像キャンバスではなく実際の Unicode SVG テキストを描画し、選択できます。HTML テキスト要素だけを求められた場合は、基線と書字方向を保って絶対配置の span に変換します。

利用できる場合はブラウザーに埋め込める原本フォントを再利用します。CLI は埋め込めないものを報告します。サブセットフォントは埋め込み可能でも Unicode 対応が欠ける場合があります。代表字形を確認してから全使用文字を確認します。代替フォントを同一とは宣言しません。太字、斜体、下線、基線、カーニング、ルビ、縦書き、RTL も確認対象です。

ネイティブパスは元の描画要素であり、スキャン文字のトレースではありません。クリップ、合成モード、透明度、パターン、Type 3 フォント、特殊な注釈は別途視覚確認が必要です。汎用抽出器は初稿作成用で、完全な PDF 描画エンジンではありません。

## スキャンと多言語

1. 代表ページを十分な解像度で描画し、文字体系をすべて目視確認します。本番バッチでは言語を明示します。`auto` は最初の診断であり、全言語を認識できた証拠ではありません。
2. macOS Vision と Tesseract は指定言語を別々に認識してから位置情報で暫定統合します。競合を確認してください。漢字に見える結果は韓国語の誤読、ラテン文字は仮名や発音区別符号の誤認識かもしれません。
3. 別エンジンには `--ocr external --ocr-command-json '["python", "adapter.py", "{image}", "{output}", "{languages}"]'` を使えます。引数はシェルを介さず渡されます。アダプターは `page-schema.md` の JSON を `{output}` または標準出力に書きます。
4. ローカル OCR が動かない場合は、ホストで許可された画像認識・文書ツールを使用します。正確な原文、言語、座標を保持して取り込み、欠落を翻訳、推測した解答、辞書生成のふりがなで補いません。
5. 色付き領域、段組、セル、罫線、ページラベル、装飾を独立形状にします。本来のイラストだけを画像素材として抽出します。必要な行と段落の境界を保ち、枠に合わせるため段落全体を一行に押し込みません。
6. 不確かな文字は追加テキスト層や付録も参照できますが、相違は実際のページに照らして解決します。補足の書き起こしにも誤字や重複 ID があり得ます。

ページ JSON を編集したら `refresh <output>` でビューアーと文字を再生成します。`--resume` は処理済み・手修正済みページを保持します。意図的に再処理する場合は `--resume --reprocess --pages <range>` を使います。対象範囲が置換され確認フラグもリセットされるため、先に手修正をバックアップします。

## 受け入れ確認

実ブラウザーで、同じ倍率の原本画像と全対象ページを比較します。初回読み込み、高速なページ切り替え、回転、真の白紙、長いページから短いページへの移動、原文のコピーと検索を確認します。ローカルで渡す場合は `file://` も試します。ページ変更時に先頭へ戻し、データ取得失敗を白紙扱いしません。

証拠が揃って初めて四つの確認項目を完了にします。OCR 信頼度、ページ数、ビルド成功、良い見本、一枚の画像では全文書の忠実性は証明できません。未解決事項は `audit.json` と納品説明に明示します。

## 画像の規則と既存出力の更新

寸法だけで画像を図版と断定できません。広い余白のある PDF ではスキャンが用紙の 59% しか占めない場合があり、複数の画像タイルが一ページを構成する場合もあります。抽出器はクリップ後の配置、幅と高さ、矩形の和集合面積で判定し、疑わしい画像を素材として保存する前に除外します。小画像も `illustration_candidate`、`reviewed: false` で始め、原本比較で独立した図版と確認するまで表示しません。ビューアーも行列だけの配置やタイルを含め幾何判定します。bbox を小さくしたり確認フラグを付けたりしてスキャン背景を戻してはいけません。

本物の独立図版は素材と原本の領域を確認し、必要なら段落やページ部分を切り離して、ページ JSON に `role: "illustration"`、`reviewed: true` を設定します。保守的な判定にかかる大写真・図版は明示的に分離または再構築します。判定は文字があると断定するものではありません。`refresh <output>` で再生成します。未確認の候補は監査で合格になりません。

OCR をやり直さず手修正の文字を保持して旧出力を更新するには、新版スキルのルートで実行します。

```sh
python scripts/run.py refresh "/path/to/outputs/example"
```

更新時にページ JSON を移行し、疑わしいページ画像を `images` から `excluded_images` のメタデータへ移し、他の未承認画像を候補にします。変更ページの確認フラグはリセットしますが、文字、手作業の図形、注記は保持します。元の画像ファイルは削除・移動しません。図版として公開せず、公開前に素材ディレクトリを確認してください。欠けた文字や配置を再構築して原本を確認した後に合格を記録します。更新はビューアーとページデータを再生成しますが、公開済みのコピーは利用者が許可した公開手順で再配置が必要です。
