# 原本に近づける反復手順

[中文](../../zh/references/fidelity.md) | [English](../../../references/fidelity.md) | [日本語](fidelity.md)

## 目標と役割

目標は原 PDF のページです。汎用テーマを整えることではありません。`build` は初稿を抽出するだけで、Agent が分析、再構築、確認、修正を続けます。任意のスキャンを自動で完成レイアウトにするスクリプトではありません。実行可能な具体的修正があれば続行します。フォント不足、判読不能な原本、ブラウザー/OCR 不在で進めない場合は、ページ記録を保ち、残る差異と復旧方法を具体的に伝えます。

別文書向けに手調整した配置を汎用変換器として流用しません。描画技法や読書 UI は再利用できますが、寸法、分類、色、領域、書体は新しい PDF 自身から導きます。

## 1. 全体確認と原本分析

対象範囲全体を構築した後に実行します。

```sh
python scripts/run.py analyze outputs/book
```

- `analysis/contact-*.jpg` は一枚 24 ページの原本一覧です。
- `analysis/00001.json` は原本の色と、連結色領域から得た面・罫線の候補です。表示 PDF 座標を使います。フォントや角丸を認識せず、長方形との断定もしません。文字の穴、写真、グラデーションに影響されるため、確認してから使います。字形領域をトレースして文字の代わりにしません。
- `reconstruction-plan.json` は全選択ページ、暫定レイアウト分類、作業を記録します。`family_override` と `notes` は手動判断を保持します。分類は参考にすぎず、見出し、表、フッター、色、例外は個別確認が必要です。

種類ごとに再構築した後、全ページを確認します。パネル、段組、セル、図、イラスト、本文、注記を分け、不可視 OCR、混在、画像タイルに注意します。原本参考画像は通常の公開内容から分離します。

## 2. 再構築と同期

ネイティブページは有効な基線、ベクター、フォント、本物の図版を保持します。未対応クリップ、透明度、注釈、Type 3、文字対応も確認します。スキャンでは座標付き OCR と独立 CSS/ベクターを組み合わせ、欠けた面や罫線を復元します。スキャンを消すだけでは再構築になりません。

ページ JSON を編集するかパッチを使います。

```sh
python scripts/run.py apply-layout outputs/book --page 12 --json work/page-12-layout.json
python scripts/run.py refresh outputs/book
```

パッチで変更できるのは `blocks`、`text`、`shapes`、`images`、`web_layout`、`background_color`、`reference_image` で、合格フラグは設定できません。汎用 SVG に戻すには `web_layout: null` を明示します。変更時に確認をリセットします。OCR/文字だけを更新して手動レイアウトを残した場合は `layout_needs_sync` が合格を止めます。`apply-layout` で両方を同期してください。表示文字、`blocks`、抽出全文、検索内容を一致させます。

原寸を基準に塗り、線、角丸、間隔、行高、基線、字間、幅、太さ、斜体、下線、縦書き/RTL、重なりを合わせます。ルビや上付きは原本を拡大し、実在する内容だけを転記します。フォントは名前だけでなく字形と行幅で確かめます。復元不能な原フォントや置換差異は未解決として明示します。

## 3. 実際の既定 Web 表示を撮影

更新時に `qa/capture-requests.json` ができ、ページごとの現行 `render_fingerprint`、相対 URL、画像・メタデータ名を示します。必要ならローカル HTTP を使い、ホストで許可された実ブラウザーツールの実際のインターフェースを確認します。別の OCR スキルは不要ですが、画像を読むだけのツールはブラウザー描画器ではありません。

`index.html?qa=1#page=12` を開きます。ページ専用表示で読書 UI を隠し、1 PDF ポイントを 1 CSS ピクセルにします。`#paper[data-qa-ready="true"]` を待ち、`#pdf-replica-qa` の JSON を読みます。DOM 専用ホストでも利用でき、許可された場合は `window.PDF_REPLICA_QA` でも読めます。フォント、HTML 画像、描画フレームを待機します。記録例：

```json
{
  "page": 12,
  "render_fingerprint": "実際に準備完了したページから取得",
  "default_view": true,
  "page_only": true,
  "ready": true,
  "visible_text_elements": 42,
  "paper_bbox": {"x": 0, "y": 0, "width": 612, "height": 792}
}
```

`paper_bbox` のページ部分だけを撮り、ツールバーや外の余白を入れません。ツールの CSS/デバイスピクセルの仕様に従います。`work/browser-captures/00012.png` に保存します（JPEG も可）。実際の準備完了記録を `00012.json` に保存し、実ツールと方法を示す `captured_with` を加えます。ready、件数、指紋を推測して書かないでください。全対象を必要に応じて分割して撮影します。

PDF の参考 PNG、原本比較モード、画像背景ページ、合成テストを実 Web の証拠にしません。同じ画像同士のゼロ差分は無意味です。実ブラウザー撮影がなければ、その具体的能力を診断して未確認のままにします。存在しないツールを作ったり、レイアウトを合格にしたりしません。

## 4. 比較、原因特定、修正、再比較

```sh
python scripts/run.py compare outputs/book --captures work/browser-captures
```

`--pages 12-24` で分割できます。不足・無効を含む全対象を記録します。`qa/comparisons/` に並列図、50% 重ね合わせ、差分、指標と最大差異領域の JSON ができます。画像は `qa/captures/` にコピーし、現行内容と原本ハッシュに結び付けます。

ページの縦横比が一致する必要があります。原本だけを撮影倍率へ調整し、画面側を引き延ばして違いを隠しません。診断の既定値はチャンネル差 24、差異ピクセル比 ≤ 0.01、正規化平均誤差 ≤ 0.005、最悪の 1/64 領域の差異比 ≤ 0.10 です。「99% 再現」の保証ではありません。小さな誤字は閾値未満になり得るため、文字と言語は別途照合します。合格するために閾値を緩めません。

大きな差異から確認し、小さい文字も拡大します。全体を盲目的に動かさず、クロップ・倍率、塗り不足、領域位置、フォント度量、基線、改行、文字、ルビ、マスク、図版の原因を直します。更新、再撮影、再比較を繰り返し、共用レイアウトの例外も確認します。機能の正常動作や全体の低誤差で、局所の誤った表や失われたルビを見逃しません。

## 5. 現行版の確認と監査

実際の原本確認を終えてから実行します。

```sh
python scripts/run.py review outputs/book --pages 12 --checks text,layout,fonts,languages --note "現行の原本/Web、文字と全差異領域を確認"
python scripts/run.py audit outputs/book
```

配置・フォントには、現行内容と一致し診断範囲内の比較証拠が必要です。指紋はページ内容、フォント・図版のバイト列、実際の HTML/CSS/JS を含みます。キャッシュ時刻は正規化しますが、実変更は旧証拠を失効させます。撮影画像や原本参考画像の変更も失効します。旧版の真偽フラグだけでは足りません。白紙も原本・表示を確認し、未解決 OCR や未同期レイアウトは合格にしません。

全範囲、現行証拠、四つの実確認が揃って監査に合格します。これは記録が現行版に対応するという意味で、意味やピクセルの完全一致の自動証明ではありません。残る差異と実制限を伝えます。機器・OS・ブラウザーで字体描画が異なる場合は、その除去不能な差異を記録し、原フォントを復元できたと装いません。

## 残る差異

パッチの `remaining_differences` に原本との未解決差異を簡潔なリストで記録し、領域や実際の障害を示せます。監査に表示され、合格記録を妨げます。実際に解決してから新パッチで更新し、合格のためだけに消しません。空リストでもブラウザー証拠と原本確認は必要です。撮影前に検索強調を消し、原本と対応する既定表示にします。
