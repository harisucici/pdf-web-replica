## この検証で証明できないこと

任意の PDF のピクセル一致、万能な OCR 精度、スキャンからの原フォント復元、復旧可能なデータやパスワードがない破損・暗号化ファイルの成功は保証しません。生成文書は下書きから始まり、ページ別の確認記録を維持します。形式のクロスプラットフォーム互換性と、OCR エンジンの有無やホスト権限は別です。

## 原本ベースの手順：ローカル開発確認

`scripts/fidelity_selftest.py` は 16 の合成部品チェックに合格しました。色・領域、全作業・一覧、手動注記保持、現行証拠、安定した時刻処理、ページ・描画器変更時の失効、パッチによる合格設定と原本比較撮影の拒否、差分・最悪領域、大差異の拒否、OCR と配置の同期、画像比率、明示的残差、OCR の代替経路を含みます。画像は比較計算用で実ブラウザー撮影ではなく、任意文書の再構築済み証拠にはできません。

別の実ブラウザーテストで、新しい合成ネイティブ PDF の Web ページを `?qa=1` で開きました。選択可能な表示文字と独立面があり、原ページ画像はなく、UI を隠して正しい 360×480 の矩形と現行指紋付き準備完了 DOM 記録を得ました。アプリ変数を読めないホスト向けに DOM JSON も用意しました。撮影プロトコルの確認であり、全文書のピクセル一致や任意スキャンの自動完成を証明しません。

従来の PDF/OCR と画像描画規則も引き続き確認が必要です。CI に Windows、macOS、Linux の忠実性部品テストを追加しました。開発版は `1.1.0-dev` で、このローカル記録は公開済みやリモート CI 成功を意味しません。
